# Миниатюры изображений

Обработчик подключён к `/images` перед GraphQL, Vite и React Router. Читает файлы из `uploads` относительно рабочего каталога. В Docker каталог подключён только для чтения и исключён из контекста сборки.

Адреса: `/images/<тип>/<файл>`, `/images/<тип>/uploads/<файл>` и исторические варианты с `/images/resized/`. Имена с пробелами и кириллицей нужно кодировать через `encodeURIComponent` для каждого сегмента пути.

| Тип          | Результат                               |
| ------------ | --------------------------------------- |
| origin       | Исходные размеры, повторное кодирование |
| big          | Ширина до 1000, без увеличения          |
| thumb        | Ширина до 150, без увеличения           |
| avatar       | 200 × 200, обрезка по содержимому       |
| place_avatar | 250 × 250, вписывание на белый фон, PNG |
| dot_thumb    | 40 × 30, обрезка по содержимому         |
| slider_thumb | 300 × 400, обрезка по содержимому       |

Пропорции сохраняются; учитывается EXIF-ориентация. Анимация не сохраняется: используется первый кадр. Метаданные удаляются. Для обрезки и вписывания применяется [API sharp](https://sharp.pixelplumbing.com/api-resize/). Вход ограничен 40 миллионами пикселей.

Поддерживаются GET, HEAD и ETag. В production успешный ответ кешируется на 30 дней, в разработке — `no-store`. Файлам после изменения нужно давать новые имена: прежний URL может оставаться в браузере и Varnish до истечения срока. Отдельного дискового кеша миниатюр нет. Ошибки не кешируются: 400 для некорректных адресов и типов, 404 для отсутствующих файлов, 422 для неподдерживаемых или повреждённых изображений. Выход за каталог, скрытые файлы и внешние символические ссылки запрещены.

Проверка: `npm run test:images`. После добавления зависимости sharp существующий Docker-образ приложения нужно пересобрать.
